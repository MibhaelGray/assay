# Operations

How the project runs day to day: where the data comes from, every scheduled job, the headless research passes, and setting up the Mac. Back to the [README](../README.md).

## Data and jobs

Everything runs on one Mac that stays on, plugged in and logged in. The nightly job stashes any edits in progress around its `git pull` and commits only the files it writes.

Bars and earnings dates come from Yahoo Finance through `yfinance`, with no login. Bids and asks for orders come from the IBKR paper gateway. The headless passes read the market from Yahoo (`fr quotes`); a pass run in the Claude app can use the IBKR connector. Web research feeds the research passes as context, not as stored data. Option data is not collected and doesn't inform a trade decision.

Since 2026-11-16 the live IBKR account subscribes to US market data (the US Securities Snapshot and Futures Value Bundle and the US Equity and Options Add-On Streaming Bundle, non-professional) and shares it with the paper account, so the paper gateway quotes stocks in regular hours over the API as well as outside them (before that, regular-hours quotes were refused with IBKR error 10089). The paper account borrows the live login's data, so logging in to the live account anywhere else (Client Portal in a browser, the mobile app, TWS) cuts the gateway's quotes off with error 10197. Log out there and restart the gateway (`docker restart deploy-ib-gateway-paper-1`); `fr paper enter` restarts it on its own when it sees that error.

Yahoo is unofficial and can miss a split on its first day. `fr bars` repairs that for ETFs (QUAL and MTUM on 2026-11-05) and lists any other move of 40% or more in the last five sessions as `suspect`, so read its output.

| Command | When (ET, trading days) | Writes |
|---|---|---|
| `fr bars` | 16:30 | `bars_daily/`, from Yahoo: the ETFs and stocks, the leveraged funds, AGG, and VIX, VIX3M and the 10-year yield |
| `deploy/run.sh nightly` | 19:00 | runs `fr brief` and the rows below, commits what it and the day's passes wrote under `journal/`, pushes |
| `fr brief` | in the nightly job | `journal/briefs/<as_of>.json`: regime, factor pairs, technicals, forced flows |
| `fr earnings` | in the nightly job | `journal/reference/earnings.json`: earnings dates for every stock the screen covers, from Yahoo Finance: the largest stocks, basket members and held names nightly, the wider tier 150 a night (see "The universe" in [signals.md](signals.md#the-screen-and-the-dashboard)) |
| `fr gaps` | in the nightly job | `journal/reference/earnings_gaps.json`: what stocks did after earnings gaps, against SPY |
| `fr scan` | in the nightly job | `journal/scans/<as_of>.json`: tonight's stock and basket candidates |
| `fr screen` | in the nightly job | `journal/screens/<as_of>.json`: every stock, ETF, basket and factor pair checked against the setups in `journal.SETUPS`; the best 40 with what triggered each and a one-line chart verdict. The dashboard shows it; the passes build their own live screen |
| `fr paper side` | 10:15 PM and 11:45 PM (Sun-Thu), 11:15 AM and 2:15 PM | `journal/paper/side/`: side facts for each stock in the night's verdicts, pulled once before the open: from Yahoo, short interest, estimate changes, ratings and targets, insider dealing; since 2026-11-23, from IBKR's public stock-loan file (`borrow.py`, FTP, no gateway or login), the yearly fee to borrow the stock and the shares available. No research pass reads them; `fr paper side report` scores each fact against how the stocks then did, night by night |
| `fr paper holds` | any time, by hand | every idea, taken or passed, scored as if held 1 to 10 sessions, with and without its stop: where the result builds, and how long the takes' and the ranking's edge lasts. Rebuilt from the proposals and the bars each time; nothing stored. No research pass runs it |
| `fr paper depth` | inside a pass, before judging | how much research each candidate got, read from the pass's own Claude Code transcripts: each name's agents, searches and pages opened, names with no agent or sharing a crowded one, and the pass's and agents' models against the rule (Fable 5.2 high judges, Sonnet 5.5 medium researches); a name under 8 searches or 5 pages read is flagged and noted, not sent a second agent (since 2026-11-19). `fr paper propose` keeps the night's measurement in `journal/paper/research/` |
| `fr baskets check` | monthly, and before adding a basket | prints whether each themed basket is a real basket: over 120 sessions, each member's daily return after its hedge's part is taken out must correlate at least 0.25 with the rest of its basket's, and the basket must average 0.35 (`basket_check.py`). It changes nothing; `--json` for the numbers |
| `fr market` | by hand | tonight's market rows for the dashboard as a file: factor board, regime, forced flows |
| `fr serve` | any time | serves the dashboard at http://localhost:8765 with a Refresh button that updates every panel in about 2.5 seconds: the paper account's fills, today's bar for every name from one bulk Yahoo quote (a five-day pull runs behind the first refresh each day to catch dividends and splits), the book's 15-minute P/L, and the brief and screen rebuilt from those bars for display only (a refresh never writes them to the journal). Earnings dates over 12 hours old update in the background, so they can't hold it up |
| `fr dashboard` | any time | `dashboard/local.html`, a local copy of the dashboard built from the journal, and opens it |
| `fr publish --pull` | every 15 minutes (the `publish` job), or by hand | pulls today's prices and the paper account as the local Refresh button does, then pushes the dashboard to the public site https://mibhaelgray.github.io/etf-factor-rotation/ (the repo's `gh-pages` branch, which holds only that page) if it changed. The site's Refresh button loads the newest copy |

**The swing book (live since the night of 2026-11-15).** One swing book with $1,000,000 and, since 2026-11-22, a $25,000 book that trades the same takes at its own size (`journal/paper/book.json`); the first book's record is in `journal/archive/first-book-2026-11-15/`. Three research passes a day judge the live screen, and an order job trades what they record (the `swing-pass` skill; prompts in `deploy/passes/swing-*.md`; schedule from `python3 deploy/launchd/install.py`). The rules a pass works under are in the skill and PROJECT.md: it ranks every candidate (about 40 a pass since 2026-11-16) and every take at conviction 3 or more is entered, strongest first until the book's capital is in use, each with its own time limit (1-10 sessions) and stop (1-8%). Since 2026-11-16 each trade is sized by its risk (`rules.side_dollars`): dollars a side = the book's capital x 0.15% x (1 at conviction 3, 1.5 at 4, 2 at 5) / the stop, so every conviction-3 trade loses $1,500 of the $1,000,000 if stopped: $18,700 a side on an 8% stop, $30,000 on 5%, $50,000 on 3%. A side is never over 6% of capital or 0.25% of a leg's 20-day average dollar volume, and the trade keeps how it was sized under `sizing`.

| Command | When (Central) | Writes |
|---|---|---|
| `fr pass night\|morning\|midday` (launchd `pass-night`, `pass-morning`, `pass-midday`) | 7:30 PM (Sun-Thu), 8:45 AM, 12:00 PM | runs the pass headless (see "Research passes outside the Claude app"); its result in `data/pass-logs/<session>-<pass>.json`, its research note in `journal/research/<session>-<pass>.md` |
| `fr screen --live night\|morning\|midday` | inside a pass, at its start | `journal/screens/live/<session>-<pass>.json`: the whole universe screened on the latest Yahoo prices (after-hours, pre-market or regular session). The night screen also asks the gateway (client id 93) for each candidate's overnight bid and ask and drops any whose own legs are over 2% wide or have no overnight market, refilling the list from the next names (since 2026-11-18); the default hedge's overnight spread is shown, not gated |
| `fr paper propose <draft>` | inside a pass, when it finishes | the pass's verdicts and ranks in `journal/paper/proposals/`, and its hold, exit or extend for each open trade in `journal/paper/pass_reviews/` |
| `fr paper enter` | every minute | `journal/paper/entries/`: once a pass has recorded, its takes as orders that hit IBKR's bid or ask, and the exits it asked for. Nothing is left resting (since 2026-11-16): the order is a limit at the bid or ask, because IBKR's overnight venue takes nothing else, and whatever it didn't fill at once is cancelled before the run ends. No quote, or a spread over 2% on any leg: nothing is sent and the trade is passed on, never to enter (since 2026-11-18). Overnight, a leg the gateway sends nothing for while it quotes SPY has no overnight market and is passed on too; any other missing quote is a gateway fault, so that trade still waits and retries every 15 minutes. A trade's legs don't go out together: the leg hardest to fill (the one whose dollars are largest against its 20-day average dollar volume, kept as `lead`) is ordered in full, and each other leg only up to the share of the lead that has filled, a few seconds behind it in the same run and then every minute while the trade is part of the way in (`rules.lead_leg`, `rules.entry_due`). In the regular session it also checks every open trade against its stop every ten minutes (`entries.STOP_EVERY`; every two minutes from 2026-11-18 to 11-22), on the same Yahoo latest-minute prices the close job uses, and a trade past it exits at once, all legs together at the bid or ask; a stop exit with no gateway quote isn't sent, is tried again at the next check, and otherwise goes into the closing auction |
| `fr watch` | every 5 minutes | `data/watch.json`: the watchdog (since 2026-11-17). It sends a phone alert through the ntfy app (topic in `FR_NTFY_TOPIC` in `.env`), through Telegram when `FR_TELEGRAM_TOKEN` (the owner's bot, from @BotFather) and `FR_TELEGRAM_CHAT` (find it with `fr watch --telegram-chats` after messaging the bot) are set, and as a Mac notification, when a scheduled job's last run exited with an error, a scheduled pass has no successful log 75 minutes after it started, the order job's last two runs both had a trade waiting for a quote, the paper gateway fails two probes in a row (outside IBKR's nightly reset, 11:30 PM to 1:15 AM ET), or the gateway is up but refused a quote for SPY with IBKR error 10197 on two checks in a row while some session could take an order. 10197 means the owner's live IBKR login is open elsewhere, such as the phone app; the alert says to log out there, since no order can go out until then, stop exits included. A second IBKR username for the phone avoids it for good. The same alert isn't repeated for 3 hours (a job's for a day). Alerts never carry account numbers, positions or dollars. `fr watch --test` sends a test alert. Separately, each scheduled pass sends "started", "recorded" or "FAILED" (passes.py), and the order job sends "<pass> pass traded" once it has acted on a pass's takes, in counts only (`entries.traded_note`) |
| `fr paper close` | 2:45 PM | `journal/paper/exits/`: time limits, and stops not already taken out during the day, sent into the closing auction |
| `fr paper sync` | 3:20 PM | `journal/paper/fills/`: the day's fills, commissions, positions and account value |

The night pass skips Friday nights; the morning and midday passes run only on trading days. A by-hand order labelled `cleanup-<trade id>` (no `|SYMBOL`) is counted against that trade in the fill's own symbol, so a sync that rewrites the day's fills can't reopen it.

The dashboard page lives in `dashboard/page.html`. The Refresh button only appears under `fr serve`. A refresh during the session stores a partial bar for the day, so the screen and the proposals' plan results wait for a session until its bars have been pulled after 4:15 PM ET. `fr dashboard` wraps the page with `dashboard/shim.js` (a stand-in for the claude.ai runtime) and `dashboard/tokens.css`, and embeds tonight's market rows, so it opens from disk with no server. Charts load d3 from a CDN.

Market data lives on this Mac's disk under `FR_DATA_ROOT` (default `data/` in the repo). The journal (briefs, scans, screens, research notes and the paper book) travels through GitHub: the nightly job commits and pushes what it wrote and what the day's research passes recorded.

## Research passes outside the Claude app

Since 2026-11-16 the swing book's three passes run as launchd jobs, not as Claude app tasks: `deploy/run.sh pass-night` (and `pass-morning`, `pass-midday`) runs `fr pass <name>` (`passes.py`), which starts Claude Code headless with the pass's prompt from `deploy/passes/`. A headless run pins the models, which the app can't: the judge runs on Fable 5.2 at high effort (`--model claude-fable-5-2 --effort high`) and every research agent on Sonnet 5.5 at medium effort (`CLAUDE_CODE_SUBAGENT_MODEL=claude-sonnet-5-5`, and the prompt tells it to spawn agents with `model: "sonnet"`, `effort: "medium"`). A headless run gets 200 web searches by default, shared by all its agents, which ran out on 2026-11-16; `passes.py` raises it to 2,500 with `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION`; `fr paper depth` checks both in the record. It signs in with `FR_CLAUDE_TOKEN` from `.env` (from `claude setup-token`) and finds the Claude Code installed by the desktop app.

The run uses `--permission-mode dontAsk` with an allowlist: it can read files, search the web, spawn research agents, write its draft to `data/pass-drafts/`, write its research note under `journal/research/` and edit `journal/paper/lessons.md`, and run only `fr screen --live <pass>`, `fr paper propose` (its own draft), `fr paper postmortem`, `fr paper depth`, `fr paper hedges` and `fr paper status`. Everything else is refused. It has no IBKR connector, so market numbers come from `uv run fr quotes SPY QQQ IWM ^VIX ^TNX CL=F ES=F NQ=F` (Yahoo). A pass has 150 minutes. Each run's result (turns, agents, minutes, anything refused, the final message) is in `data/pass-logs/<session>-<pass>.json` and its output in `~/Library/Logs/factor-rotation/pass-<name>.log`.

`fr pass late` is a fourth pass, run by hand only (since 2026-11-16): a second pass in the night window, for the same session as the night pass. It screens with `fr screen --live late`, leaves out the names the night pass judged, records as `"pass": "late"` and is traded by `fr paper enter` like any other pass. It writes no post-mortems or lessons. It can be run again the same night: each further run records as `late2`, `late3` or `late4`.

`fr pass <name> --shadow` runs a pass on a copy of the journal in `data/shadow-journal` with `FR_PAPER_SEND=0`, so it records and trades nothing that counts: use it to try a prompt change.

## Setup (macOS)

1. **Paper account:** in Client Portal, open the paper account (Settings → Account Settings → Paper Trading Account) and note its username and DU account number. The account must be on IBKR Pro (Lite accounts can't use the API). Expect an IB Key approval on your phone about once a week, when the gateway's session expires.
2. **Software:** install Docker Desktop (Settings → General → Start Docker Desktop when you sign in), `uv` and git. Clone this repo, set `git config user.name` and `user.email` in it, and give the Mac an SSH key with write access to the GitHub repo and no passphrase, so the nightly job can push unattended.
3. **Settings:** copy `.env.example` to `.env` and fill it in. Put the paper username and password in `.env.paper` (`TWS_USERID=` and `TWS_PASSWORD=`; git ignores both files).
4. **Start the gateway:** `docker compose -f deploy/docker-compose.yml up -d`. It restarts with Docker Desktop, IBC logs it in and restarts it at 11:55 PM ET each night. It publishes the paper API on 127.0.0.1:4002 only. `uv run fr paper status` checks the connection and the account.
5. **Keep it awake on power.** Jobs that come due while the Mac sleeps run late, when it wakes. In System Settings, turn on automatic login, and under Battery → Options turn on "Prevent automatic sleeping on power adapter when the display is off". Or from a terminal:
   ```bash
   sudo pmset -c sleep 0 disksleep 0
   ```
   Leave the lid open, or closed with an external display attached; a closed lid without one sleeps regardless. Each job also runs under `caffeinate`, so the Mac stays awake until it finishes, and the `keep-awake` job holds off idle sleep overnight for the order job and the night pass.
6. **Install the schedules:** `python3 deploy/launchd/install.py`. It converts the New York schedule to the Mac's time zone (rerun it if that changes) and installs one launchd agent per job. `--dry-run` shows the plists without installing, `--uninstall` removes them. Keep the repo outside `~/Documents`, which launchd jobs can't read without Full Disk Access.
7. **First run:** `uv run fr bars` backfills 5 years of bars (no gateway needed).

Logs: `~/Library/Logs/factor-rotation/<job>.log`. To run a job now: `launchctl kickstart gui/$(id -u)/com.factor-rotation.nightly`.

## Moving to another Mac

1. Set up the new Mac with steps 1–3 and 5 above, but don't start the gateway yet.
2. On the old one: `python3 deploy/launchd/install.py --uninstall`, then `docker compose -f deploy/docker-compose.yml down`. One gateway per username, so stop this one first.
3. Copy `data/` across (Remote Login on, on the new Mac): `rsync -az data/ newmac.local:<repo path>/data/`. Bars can be pulled again from Yahoo; the pass logs and the option chains stored up to 2026-11-05 can't.
4. On the new Mac: start the gateway, install the schedules and kickstart `bars` to check it works.

## Backup

The journal is in git. `data/` is on this Mac's disk only: daily bars (re-downloadable), pass logs and drafts, and the option chains stored up to 2026-11-05 (not re-downloadable, and no longer used). Copy it somewhere else now and then if the pass logs matter to you.
